# coupangctl 가치·실현 가능성 연구

검토일: 2026-09-01 (Asia/Seoul)

이 문서는 공개된 1차 자료와 저장소에 남아 있는 합성·비식별 연구 결과를 바탕으로, `coupangctl`에서 실제로 만들 가치가 있는 범위와 운영 경계를 정리한다. 쿠팡 계정, 쿠키, OTP, 원시 주문 응답은 사용하거나 기록하지 않았다.

## 결론

가장 가치 있는 제품은 “쿠팡을 대신 조작하는 에이전트”가 아니라 **사용자가 직접 인증한 자신의 주문 이력을 로컬에서 검색·분석·내보내는 개인 데이터 레이어**다. 이 방향은 이미 확인된 주문 문서의 구조화 데이터와 잘 맞고, 결제·구매 자동화보다 위험이 작다.

우선순위는 다음과 같다.

1. 읽기 전용 주문 이력 동기화와 중복 없는 로컬 원장
2. 기간·카테고리·판매자별 지출, 반복 구매, 배송 상태 분석
3. 사용자가 명시한 상품의 가격·배송·평점·리뷰 비교
4. 동일 typed core를 CLI와 MCP에서 공유

## 왜 이 범위가 실질적인가

쿠팡의 개인정보 처리방침은 서비스 이용·방문·검색 기록을 분석해 관심과 선호를 파악하고 개인화된 쇼핑 경험을 제공한다고 설명한다. 이는 사용자가 자신의 구매·검색 흔적을 직접 조회하고 정리하려는 수요가 단순 상품 검색보다 넓을 수 있음을 뒷받침한다. 다만 같은 문서는 이메일, 이름, 전화번호, 서비스 이용 이력 등이 개인정보 항목임을 명시하므로, 로컬 저장소 역시 민감한 개인 데이터로 취급해야 한다. [쿠팡 개인정보 처리방침](https://privacy.coupang.com/en/center/coupang/)

저장소의 기존 프로브는 주문 목록의 SSR 문서 안에 주문일·총액·상품/판매자·수량·배송 일정·취소/반품 상태·재주문 가능 여부 등이 구조화되어 있음을 확인했다. 이 필드 조합은 “최근 주문 보기”보다 다음과 같은 반복 사용 가치가 있다.

- 월별 총지출과 배송비·할인액을 분리해 가계 기록에 활용
- 같은 상품/유사 상품의 재구매 후보와 마지막 구매 시점을 찾기
- 배송 지연·미도착 상태를 한 화면에서 점검
- 원본 사이트의 UI나 검색 기간 제한과 독립적으로 개인 기록을 보존

이는 외부 판매자용 Open API를 소비자 계정에 억지로 적용하는 것과 구분해야 한다. 쿠팡의 공식 Open API 문서는 WING 판매자 계정과 상품 등록·관리 워크플로를 전제로 하며, 소비자 주문 이력 API로 설명되어 있지 않다. 따라서 소비자 기능은 공식 구매자 API가 있다고 가정하지 말고, 보호된 사용자 세션에서 읽기 전용으로 획득한 문서를 좁은 어댑터에서 파싱하는 것이 현실적이다. [Coupang Open API 개요](https://developers.coupangcorp.com/hc/en-us/articles/360033917473-Coupang-OPEN-API), [상품 API 워크플로](https://developers.coupangcorp.com/hc/en-us/articles/360033642034-Product-API-Workflow)

## 구현 가능성 및 가장 큰 리스크

현재 연구에서 상품·리뷰 공개 표면은 구조화 JSON으로 재생 가능했지만 주문 목록 문서는 순수 Node HTTP 재현에서 `403/406`이 발생했다. 그러므로 첫 버전의 동기화는 다음 경계를 지켜야 한다.

- 인증과 보호된 주문 문서 획득에만 격리된 Chromium 세션 사용
- 브라우저에서 클릭·스크롤로 카드를 긁지 않고, 문서의 구조화 데이터만 파싱
- 파싱·정규화·SQLite 조회·분석·내보내기는 브라우저와 분리
- 엔드포인트, 헤더, 응답 모양은 사설 구현 세부사항으로 취급하고 좁은 어댑터 뒤에 숨김
- 실패 시 재시도 횟수와 속도를 제한하고, CAPTCHA/OTP 우회·대량 수집을 시도하지 않음

쿠팡 서비스 이용 정책은 회사가 제공하지 않은 비정상적인 방법으로 시스템에 접근하거나 이용하는 행위, 허락 없이 게시 정보를 복제·변조하는 행위를 시스템 부정 행위 예시로 든다. 따라서 자동 로그인 우회, 보호 장치 회피, 공격적 병렬 요청, 제3자 데이터 수집은 제품 범위에서 제외해야 한다. [쿠팡 서비스 이용 정책](https://www.coupang.com/np/policies/service)

## 데이터 설계와 안전한 기본값

SQLite는 단일 파일·트랜잭션·인덱스·SQL 조회·장기 호환성을 제공하므로 개인용 내보내기 원장에 적합하다. SQLite 공식 문서도 애플리케이션 파일 형식으로서 단일 파일과 접근성, 안정성을 장점으로 설명한다. [SQLite as an Application File Format](https://www.sqlite.org/appfileformat.html)

권장 저장 모델은 `orders`, `order_items`, `shipments`, `products`, `price_observations`, `sync_runs`처럼 분석 단위로 정규화하고, 원시 HTML/JSON과 주소·전화번호·결제수단은 기본 저장하지 않는 것이다. 동기화는 날짜/주문 식별자의 해시나 내부 키를 사용해 멱등적으로 수행하고, 삭제·보존 기간·전체 내보내기/폐기 명령을 제공해야 한다.

MCP를 추가할 때는 읽기 도구를 명시적으로 좁혀 `orders.list`, `orders.spend`, `orders.reorder_candidates`, `products.compare` 정도로 시작한다. MCP 사양은 호스트가 사용자 데이터 노출과 도구 호출 전에 명시적 동의를 얻고, 접근 제어·출력 보호를 적용해야 한다고 권고한다. 도구 입력 검증, 속도 제한, 민감한 작업의 사용자 확인도 보안 고려사항으로 제시한다. 따라서 MCP 서버는 로컬 stdio를 기본으로 하고, 네트워크 노출·임의 SQL·원시 payload 반환을 허용하지 않는 것이 타당하다. [MCP 2025-03-26 Specification](https://modelcontextprotocol.io/specification/2025-03-26/index), [MCP Tools Security Considerations](https://modelcontextprotocol.io/specification/2024-11-05/server/tools)

SQLite 데이터베이스 파일을 신뢰할 수 없는 위치에서 열거나 MCP 입력으로 SQL을 받는 경우에는 SQLite가 권고하는 `trusted_schema=OFF`, 입력 크기 제한, authorizer/timeout, 무결성 검사 등을 검토해야 한다. 가장 안전한 첫 버전은 임의 SQL 도구 자체를 제공하지 않는 것이다. [SQLite Defense Against the Dark Arts](https://www.sqlite.org/security.html)

## 검증 가능한 첫 릴리스

완료 기준은 기능 수가 아니라 다음의 증거로 잡는 편이 좋다.

- 합성 주문 fixture로 파서가 주문·상품·배송·할인 금액을 안정적으로 정규화
- 같은 페이지를 두 번 동기화해 행이 중복되지 않음
- 페이지 중간 실패 후 checkpoint에서 재개하고 이미 처리한 페이지를 안전하게 건너뜀
- PII/쿠키/OTP/원시 응답이 로그·fixture·에러 메시지에 나타나지 않음
- 가격·배송·평점 비교는 시점과 출처를 함께 반환하고 광고/추천 표시를 보존
- 구매·결제·취소·반품·교환·계정 설정 변경 도구가 존재하지 않음
- MCP 호출은 정해진 JSON 응답 shape, 입력 검증, timeout, 호출 감사 로그를 가짐

현재 저장소에서 `npm run typecheck`는 통과했다. 인증이 필요한 네트워크 프로브는 실행하지 않았으며, 이는 자격증명·개인 주문 데이터에 접근하지 않는 안전한 기본 검증이다.

## 추천하지 않는 투자

- 결제·구매·취소·반품을 자동화하는 에이전트
- CAPTCHA/OTP나 쿠팡의 비정상 접근 방어를 우회하는 기능
- 소비자 계정과 판매자 Open API 키를 한 제품 흐름에 섞는 것
- 원시 주문 payload/주소/송장/쿠키를 장기 보관하는 것
- 모델에게 임의 SQL과 원시 개인 데이터를 직접 노출하는 MCP 서버

이 범위를 지키면 `coupangctl`의 차별점은 브라우저 자동화 자체가 아니라, 사용자의 구매 기록을 재사용 가능한 로컬 데이터셋으로 바꾸고 설명 가능한 분석을 제공하는 데 생긴다.
